## ✨ ひとことで

PhotoSwipe は iPhone の写真ライブラリを読み込み、あとは**フルスクリーンでスワイプするだけ**：上スワイプで削除キューへ、下スワイプでお気に入り、左右スワイプで閲覧。溜まったらゴミ箱で一括確認・削除 —— **削除前に解放できる容量が見えます**。

## 🔥 主な特徴

| | 機能 | 説明 |
|:---:|---|---|
| 🗑️ | **削除キュー + 容量見積もり** | 上スワイプはすぐには削除しない。確認前に解放可能な容量を表示。1 枚ずつの取り消しも可能。削除後も「最近削除した項目」に 30 日間残る |
| 🧠 | **スマート整理（4 入口）** | 類似写真・連写を自動グループ化 · 月別整理 · 90 日前の古いスクショ · ぼやけ検出 |
| 👆 | **グループ一括処理** | 「この 1 枚を残して他の 7 枚を削除」—— 連写 8 枚をスワイプ 1 回で処理 |
| 📂 | **分類はシステムと完全一致** | iOS のスマートアルバムを直接読み込み：セルフィー・スクリーンショット・ライブ写真・動画・パノラマ・ポートレート… |
| 📏 | **ファイルサイズで並べ替え** | 容量を食う動画を狙い撃ち（標準の写真アプリにはできないこと） |
| 🎬 | **動画フルスクリーン再生** | ズーム・ジェスチャー・シークまで、スワイプの流れの中で完結 |

## ✋ 機能

### 分類

分類は iOS のスマートアルバム（`PHAssetCollection`）を直接読み込むため、標準の写真アプリと完全に一致します。独自のフィルタリングは行いません。

| 分類 | 内容 |
|---|---|
| すべての写真 | ライブラリ全体、撮影日の新しい順 |
| セルフィー | インカメラで撮影した写真 |
| スクリーンショット | スクリーンショット |
| ライブ写真 | Live Photo |
| 動画 | すべての動画（フルスクリーン再生可） |
| パノラマ | パノラマ写真 |
| ポートレート | 奥行き情報を持つ写真 |
| お気に入り | システムの写真アプリでお気に入り登録した写真 |

### ジェスチャー

| ジェスチャー | 動作 |
|---|---|
| 左右スワイプ | 前 / 次の写真へ。指に追従する連続ページング |
| ⬆️ 上スワイプ | 削除キューに追加（**すぐには削除されない**） |
| ⬇️ 下スワイプ | お気に入りに追加。もう一度下スワイプで解除 |
| ピンチ | 拡大。拡大中はドラッグで移動のみ（ページ送りされない） |
| ダブルタップ | 1× と 2.5× を切り替え |
| タイトル横の矢印をタップ | 4 列サムネイル一覧を展開。任意の 1 枚をタップしてそこに戻る |
| 動画をタップ | フルスクリーン再生 |

### 削除キュー

> [!NOTE]
> **設計判断**：削除は不可逆。そのため誤操作しやすいジェスチャーに結びつけず、ジェスチャーは意図の表明だけに徹し、実行は最後の一度きりの確認に集約しています。

上スワイプは写真の識別子をローカルキューに書き込むだけ。右上のゴミ箱ボタンに件数が表示され、開くと上部に**このバッチで解放できる合計容量**が表示されます。1 枚ずつの取り消し（元の位置へ即座に戻る）も、一括削除も可能。削除はシステム確認のうえ `PHPhotoLibrary.performChanges` で一括コミットされ、写真は「最近削除した項目」に入るため 30 日以内なら復元できます。キューはローカルに永続化され、再起動しても消えません。

### 並べ替え

どの分類内でも切り替え可能：デフォルト（新しい順）・ファイルサイズの降順・昇順。選択は記憶され、サイズ順のときはタイトル下に実際のサイズが表示されます。

### スマート整理

ホーム画面に 4 つの入口。「どこから手をつければいいか分からない」4 つのシーンに対応：

| 入口 | 内容 | 解析が必要 |
|---|---|:---:|
| 類似 / 連写 | 似た写真と連写を自動でグループ化 | ✅ |
| 月別整理 | 「2023 年 5 月 · 486 枚」単位で一括整理 | — |
| 古いスクショ | 90 日より前のスクリーンショットをグループ化 | — |
| ぼやけの可能性 | 明らかにピンボケの写真を自動抽出し、ぼやけ度順に表示 | ✅ |

**グループ一括処理**：残したい 1 枚までスワイプし、「この 1 枚を残して他の 7 枚を削除」をタップすると、グループの残りすべてがキューに入り自動で一覧へ戻ります。**ぼやけバッジ**：ピンボケ判定された写真には右上に「ぼやけの可能性」ラベルが付きます（表示のみで操作は妨げません）。

## 🔬 技術メモ

- **分類はシステムのスマートアルバムに一任**：`PHAssetCollection` の `smartAlbum` に判定を完全委譲し、写真アプリと完全一致。
- **削除後はインデックスを再構築**：`PHFetchResult` は削除後にインデックスがずれるため、独立配列で有効範囲を再計算し、現在ページ±1 のみ描画。
- **画像のオンデマンド読み込みとプリフェッチ**：同時に保持する画像リクエストは 3 件だけ。上限 120MB の `NSCache` と併用。
- **ファイルサイズは非公開 API 経由**：PhotoKit には提供されていないため、`PHAssetResource` から KVC で読み取り、事前に `responds(to:)` で確認。
- **類似判定は知覚ハッシュ（dHash）**：64×64 グレー → 9×8 グリッド → 64 ビット指紋。ハミング距離 ≤10 で類似とみなす。
- **総当たり比較はバケット化で打ち切り**：5,000 枚の全比較は 1,250 万回。64 ビット指紋を 4 分割した 16 ビット単位のバケットで数万回まで削減。40 枚超のバケットはスキップ。
- **連写はハッシュに頼らない**：システムネイティブの `PHAsset.burstIdentifier` でグループ化。最も正確でサムネイルも不要。
- **ぼやけ判定はラプラシアン分散**：しきい値 20、あえて保守的に —— 見逃すことはあっても、正常な写真を誤判定しない方向に倒す。
- **解析では iCloud の原本をダウンロードしない**：サムネイル取得で `isNetworkAccessAllowed` を無効化し、数 GB の通信を静かに消費する事態を回避。
- **プロジェクトは XcodeGen で記述**：リポジトリに `.xcodeproj` は含めず、`project.yml` からビルド時に生成。

## ⚠️ 既知の制限

- **「セルフィー」の範囲はシステム判定**：インカメラ撮影の写真のみ。写真アプリの結果と同じです。
- **iCloud 写真の初回読み込みは遅い**：都度ダウンロードが必要なため。ネットワーク・ストレージ状態の問題であり、ロジックの不具合ではありません。
- **7 日ごとに再署名が必要**：無料 Apple ID の一般的な制限。
- **類似・ぼやけ解析には範囲がある**：直近 5,000 枚かつローカルにサムネイルがある写真のみ。結果はローカルにキャッシュされ、新規写真は差分計算。
- **ぼやけ判定は見逃すことがある**：しきい値は保守的。軽い手ブレは検出されない場合があります。
- **App Store 未上架**：個人利用のツールという位置づけのためです。
