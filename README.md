## 简介

PhotoSwipe 读取 iPhone 相册，按系统已有分类呈现内容，用户以全屏滑动的方式逐张做出「保留 / 待删 / 喜欢」的标记，最后在待删列表中统一确认并删除。

它没有上架 App Store，没有服务器，没有账号体系，也不会上传任何照片。全部处理在设备本地完成。

开发它的直接原因是：市面上同类应用把「批量删除」这类基础功能放在订阅墙之后。

## 起因

整理两万余张照片时，系统相册只能逐张打开、逐张删除，效率无法接受。

在 App Store 找到的几款工具界面尚可，但批量删除、视频预览、按体积排序分别需要开通会员。

一个作用于本机照片的基础功能被做成订阅制，这件事本身构成了做一个替代品的动机。

凌晨三点，需求被口述给 AI。约半小时后，它变成了这个仓库的第一版。

## 功能

### 分类

分类结果直接读取 iOS 的智能相簿（`PHAssetCollection`），与系统相册「相簿」页中的分类一致，不做二次筛选。

| 分类 | 内容 |
|---|---|
| 全部照片 | 整个图库，按拍摄时间倒序 |
| 自拍 | 前置摄像头拍摄的照片 |
| 截屏 | 截图 |
| 实况照片 | Live Photo |
| 视频 | 所有视频，可全屏播放 |
| 全景 | 全景照片 |
| 人像模式 | 带景深信息的照片 |
| 喜欢 | 已在系统相册中标记喜欢的照片 |

### 手势

| 手势 | 行为 |
|---|---|
| 左右滑动 | 上一张 / 下一张，跟随手指连续分页 |
| 向上滑动 | 加入待删队列，不立即删除 |
| 向下滑动 | 加入「喜欢」；已标记的照片再次下滑可取消 |
| 双指捏合 | 放大查看细节。放大后单指拖动只平移图片，松手也不会翻页 |
| 双击 | 在 1× 与 2.5× 之间切换，还原后即可继续左右翻页 |
| 点击标题旁箭头 | 展开四列缩略图总览，点任意一张回到该位置继续滑动 |
| 点击视频 | 全屏播放 |

### 待删队列

向上滑动不会删除照片，只把照片的标识写入一个本地队列。右上角垃圾桶按钮显示当前数量。

打开垃圾桶后，顶部先给出这批照片加起来能释放多少空间；下面是可以看到队列中的全部缩略图：单张可撤回，也可以一次性删除全部。撤回的照片会立即回到浏览列表的原始位置，不需要退出重进。执行删除时系统会弹出一次确认，通过 `PHPhotoLibrary.performChanges` 单次提交，删除的照片进入系统「最近删除」，30 天内可恢复。

队列持久化在本地，关闭应用或重启设备都不会丢失。

> 设计取舍：删除不可逆，因此不绑定在最容易误触的手势上。手势只负责产生意图，执行集中在最后一次确认。

### 排序

任意分类内可通过右上角的排序按钮切换顺序：默认（最新优先）、文件从大到小、文件从小到大。选择会被记住。按体积排序时，标题下方会显示当前照片的实际大小。

### 智能整理

首页在「全部照片」下方单独开了一栏，四个入口对应四种「不知道从哪下手」的场景。

| 入口 | 做什么 | 需要分析 |
|---|---|---|
| 相似 / 连拍 | 把长得像的照片和连拍自动编成组，一组一组过 | 是 |
| 按月整理 | 按拍摄月份列出「2023 年 5 月 · 486 张」，整月进入清理 | 否 |
| 过期截屏 | 90 天前的截图单独成组，三个月内的不动 | 否 |
| 可能拍糊 | 自动挑出明显虚焦的照片，按糊的程度排序 | 是 |

**整组处理。** 进入任意一组后，底部多一个按钮：「保留这张，其余 7 张待删」。滑到想留的那张，点一下，同组其余全部进入待删队列，然后自动返回列表。整组只处理一次，不需要一张一张滑。

**拍糊角标。** 分析过的照片如果判定为虚焦，浏览时右上角会贴一个「可能虚焦」的标签。这个标签不阻塞任何操作，只是提示。

## 自己部署与生成 IPA

本项目使用 MIT 协议，欢迎部署到自己的仓库。

**没有 Mac 也可以完成编译。** iOS 应用必须在 macOS 上构建，因此这里的做法是借助 GitHub Actions 免费提供的 macOS 运行环境：代码推送到仓库后，由它完成编译并产出未签名的 `.ipa`，再通过 Sideloadly 用个人 Apple ID 签名安装到手机。

作者本人的情况也是如此：手上没有 Mac，全部编译都在 GitHub 的 macOS 机器上完成。

### 步骤

1. **Fork 本仓库**到自己的 GitHub 账号
2. 进入 `Actions` 标签页，左侧选择 `Build IPA`，点击右侧 `Run workflow`
3. 等待约 8 分钟，运行状态变为绿色对勾后进入该次记录，在页面底部 `Artifacts` 下载 `PhotoSwipe-IPA`
4. 解压得到 `PhotoSwipe.ipa`，用 [Sideloadly](https://sideloadly.io) 载入，填写 Apple ID，点击 `Start`

安装后若提示「不受信任的开发者」，前往 `设置 → 通用 → VPN 与设备管理 → 开发者 App`，选择对应的 Apple ID 并点击「信任」。

## 技术说明

**分类采用系统智能相簿。** 早期方案是用 `NSPredicate` 自行筛选，但结果与系统相册存在数量差异。改用 `PHAssetCollection` 的 `smartAlbum` 系列后，判定完全交由系统完成，一致性问题消失。

**删除后需要重建索引。** `PHFetchResult` 在删除后索引会变化，直接按 `index + 1` 取值会越界崩溃。当前实现维护独立数组，删除后重新计算有效范围，并且只渲染当前页前后各一页。

**图片按需加载与预取。** 任意规模的图库在内存中同时只保留三个图片请求，配合上限 120MB 的 `NSCache`，回滑时可立即命中缓存。

**文件大小不属于公开 API。** PhotoKit 未提供该属性，实现方式是从 `PHAssetResource` 通过 KVC 读取，取值前使用 `responds(to:)` 判断可用性，缺失时按 0 处理。这是同类工具的通用做法。

**相似照片用感知哈希（dHash）。** 把每张图缩到 64×64 灰度，采样成 9×8 网格，比较左右相邻格的大小关系，得到 64 位指纹。它对亮度、对比度、缩放都不敏感，只反映结构。两张图的汉明距离不超过 10（64 位中最多差 10 位）即视为相似；距离极近（≤4）的不限时间，其余要求拍摄时间在 30 天内，避免不同年份的相似场景被合并。

**两两比较被分桶截断。** 5000 张照片全量比较是 1250 万次。实现上把 64 位指纹切成 4 段 16 位，只有某一段完全相同才进入比较，实际比较次数降到几万次。单桶超过 40 张时直接跳过——那通常是大面积纯色等无区分度的图，比较下去只会把不相干的照片粘成一组。

**连拍不依赖哈希。** `PHAsset.burstIdentifier` 是系统原生标记，直接按它分组，准确率最高，且不需要下载缩略图，因此连拍组排在结果最前。

**拍糊用拉普拉斯方差。** 在同一张 64×64 灰度图上做四邻域拉普拉斯，统计方差。边缘越锐利方差越高，明显失焦会塌到个位数。阈值取 20，偏保守：宁可漏掉几张，也不把正常照片标成糊的。

**分析不下载 iCloud 原图。** 缩略图请求关闭了 `isNetworkAccessAllowed`，未下载到本地的照片直接跳过。否则分析几千张会悄悄消耗数 GB 流量。

**工程由 XcodeGen 描述。** 仓库中不包含 `.xcodeproj`，只有 `project.yml`，编译时现场生成工程，避免配置与源码不同步。

## 已知限制

- **「自拍」的范围由系统判定。** 仅包含前置摄像头拍摄的照片，他人代拍或使用后置摄像头拍摄的自拍不在此列，系统相册中的结果相同。
- **iCloud 照片首次加载较慢。** 未下载到本地的照片需要临时拉取，会出现等待。属于网络与存储状态，不涉及逻辑缺陷。
- **七天需重新签名。** 免费 Apple ID 的通用限制，见上文。
- **相似与拍糊分析有范围。** 默认只分析最近 5000 张、且本机已有缩略图的照片；iCloud 上未下载的照片会被跳过。结果缓存在本地，新增照片后会增量补算。
- **拍糊判定可能漏判。** 阈值偏保守，只挑明显失焦的；轻微手抖、运动模糊可能不在列表内。列表按模糊程度排序，仍建议快速过一眼。
- **未上架 App Store。** 定位是个人使用的工具，没有分发的必要。
